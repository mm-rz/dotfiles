# dotfiles インストーラーを保守する

初期環境での実行要件を増やさず、`install.sh` をリポジトリ内のファイルやツールと一致させる。

## 編集前に調査する

1. `install.sh`、`README.md`、変更対象ツールの設定を読む。
2. `git status --short` を実行し、ユーザーによる無関係な変更を保持する。
3. 次の項目を分けて確認する。
   - 実行時に必要なパッケージとコマンド
   - ビルド時の依存関係
   - リンクが必要な設定ファイルのパス
   - ツールを導入すべきプロファイル
4. 依存関係に関するチャートを `README.md` になければ追記する。あれば更新する。

## 不変条件を守る

- インストーラーは POSIX `sh` で記述する。Bash の配列、`[[ ... ]]`、`source`、プロセス置換、`pipefail` を導入しない。
- 言語ランタイム、ダウンロードツール、パッケージマネージャーのラッパー、dotfiles マネージャーが導入済みであると仮定しない。OS の標準機能と `git` だけが存在するものとする。
- コンポーネントを小さく保ち、各 `install_<component>` 関数に明確な責務を1つだけ持たせる。
- 前提コンポーネントを `component_dependencies` に宣言する。プロファイル内の記述順だけに依存しない。
- プロファイルを環境の役割ごとに保つ。デスクトップで利用できるという理由だけで、GUI ツールを `minimal`、`server`、`developer` に追加しない。
- 再実行を安全にする。可能な限り、再インストールや置換の前にコマンドの存在とリンク先が正しいか確認する。
- 既存のリンク先を上書きせず、バックアップする。
- 実行可能なインストーラーは一時ファイルへダウンロードしてから実行する。`curl | sh` のパイプラインを追加しない。
- 対応するパッケージマネージャーを明示する。現在は `apt-get` のみを対象とし、未検証のクロスプラットフォーム対応をうたわない。
- `--dry-run` では環境を変更しない。インストーラーの保守中に実際のインストールを実行しない。

## ツールを更新する

ツールを追加または変更するときは、該当するすべての接続点を更新する。

1. `component_dependencies` のコンポーネントと依存関係を追加または調整する。
2. 対応する `install_<component>` 関数を追加または調整する。
3. 適切なプロファイルだけにコンポーネントを追加する。
4. 設定ファイルを、対象範囲が最も狭い `links-*` コンポーネント（core、editor、desktop）でリンクする。
5. 公開インターフェースやプロファイルの内容を変えた場合は、`list_items`、ヘルプ、`README.md` を更新する。

導入手順と対象プロファイルが一致する場合は、既存のコンポーネントを優先する。依存関係が独立している、異なる環境で任意選択になる、または `--only` や `--skip` で個別に選択する必要がある場合は、新しいコンポーネントを作る。

対応済みパッケージマネージャーから導入できないツールについて、パッケージ名を推測したり、別のインストーラーを暗黙に追加したりしない。導入元の選択がセキュリティ、更新方法、対応環境に大きく影響する場合は、意図を確認するかユーザーに質問する。

## 検証する

インストーラーを変更したら、リポジトリのルートで次を実行する。

```sh
sh -n install.sh
./install.sh --list
./install.sh --dry-run --profile minimal
./install.sh --dry-run --profile server
./install.sh --dry-run --profile developer
./install.sh --dry-run --profile desktop
git diff --check
```

新規または変更したコンポーネントごとに、`--only` を指定した dry-run も実行する。依存コンポーネントを `--skip` する矛盾した指定を1つテストし、分かりやすいエラーで失敗することを確認する。ShellCheck が利用可能なら `shellcheck -s sh install.sh` も実行する。

出力された `Plan:` を確認し、依存先が利用側より前にあり、対象外の環境に影響していないことを確かめる。最後に差分全体を確認する。ユーザーから明示的な依頼がない限り、dry-run ではないインストールを実行しない。
